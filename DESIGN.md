# Последний фонарь — Game Design Document (MVP)

## 1. Игровое обещание

Игрок за 2–4 минуты исследует небольшую шахту, принимает понятные решения о риске и зарабатывает валюту для постоянных улучшений. В игре нет сложного обучения, надоедливых таймеров, рекламы или сетевой зависимости.

**Hook:** «Возьму ещё один кристалл — или вернусь, пока горит фонарь?»

**Целевая платформа:** мобильный и десктопный браузер. Первый деплой — GitHub Pages, без сервера и базы данных.

## 2. Основной цикл

Поверхность → новая случайная шахта → выбор направления → шаг/разрушение стены → находка → контроль заряда и места в рюкзаке → безопасное возвращение / аварийный выход / потеря заряда → получение части или всей добычи → магазин → повторить.

Ключевые управленческие решения:

- **Идти ли глубже?** У отдалённых ресурсов выше логистический риск: дорога назад тоже расходует энергию.
- **Копать ли стену?** Проход через стену стоит разрушение + шаг.
- **Возвращаться ли с полным рюкзаком?** Возможность найти ещё предметы бесполезна без дополнительной вместимости.
- **Какое улучшение покупать?** Батарея снижает риск, кирка уменьшает расход, рюкзак увеличивает потенциальный заработок, фонарь даёт больше информации.

## 3. Правила карты

- Размер 11 × 11, центр (5,5) — лестница и стартовая точка.
- Край карты непроходим, внутренние стены разрушаемы.
- Около 23% допустимых внутренних клеток — стены. Старт и четыре соседние клетки гарантированно свободны.
- 13 руд, 5 кристаллов, 2 реликвии, в том числе две руды рядом со стартом.
- Генератор принимает seed: одинаковый seed и одинаковый алгоритм дают одну карту.
- Радиус видимости считается расстоянием Манхэттена. Исследованные клетки остаются в затемнённой памяти.
- Случайная генерация не может навсегда запереть игрока: любая внутренняя стенка разрушима.

## 4. Экономика

| Действие | Энергия |
|---|---:|
| Перейти на соседнюю свободную клетку | 1 |
| Разбить внутреннюю стену | 2; после улучшения 1 |
| Подобрать ресурс, оказавшись на клетке | 0 дополнительно |
| Вернуться на поверхность с лестницы | 0; 100% добычи |
| Экстренная эвакуация | 0; 50% добычи |
| Автоматическое завершение при нуле энергии | 0; 20% добычи |

**Начальные характеристики:** 32 энергии, 6 мест, свет 2 клетки, кирка 2 энергии.

| Улучшение | Эффект уровня | Уровни | Цены (монеты) |
|---|---|---:|---|
| Аккумулятор | +6 энергии | 3 | 8 / 18 / 32 |
| Рюкзак | +3 слота | 2 | 9 / 21 |
| Фонарь | +1 радиус | 2 | 12 / 28 |
| Кирка | −1 стоимость разрушения | 1 | 14 |

Баланс прототипный; цены менять после 10–20 собственных тестовых заходов, ориентируясь на то, не получается ли купить всё за несколько экспедиций.

## 5. Состояние

### Постоянное

- `gold` — остаток валюты;
- `upgrades` — уровни четырех улучшений;
- `runsCompleted` — число завершенных экспедиций;
- `bestBanked` — рекорд награды за один заход;
- `lastResult` — итог предыдущей экспедиции.

### Текущая экспедиция

- `tiles` — двумерная карта и её ресурсы;
- `seen` — разведанные клетки;
- `player` — позиция;
- `energy` — остаток;
- `bag` — счётчик добычи каждого вида;
- `seed` — источник детерминированной генерации.

Оба блока сохраняются в localStorage после каждого успешного действия. Сохранение имеет версию `1`; будущие изменения структуры потребуют миграции.

## 6. Слои архитектуры

```text
           ┌─────────────────────────────┐
           │ Phaser Scenes (UI + input)  │
           │ BaseScene / MineScene       │
           └──────────────┬──────────────┘
                          │ dispatch action
           ┌──────────────▼──────────────┐
           │ Domain Engine (pure TS)     │
           │ step, end, buy, start       │
           └──────────────┬──────────────┘
                          │ reads/writes
           ┌──────────────▼──────────────┐
           │ Map + Balance + Types       │
           │ seed RNG, fog, economy      │
           └──────────────┬──────────────┘
                          │ save snapshot
           ┌──────────────▼──────────────┐
           │ Storage → localStorage      │
           └─────────────────────────────┘
```

**Зависимости направлены вниз.** Домен не импортирует Phaser, так что правила можно проверять тестами Node. Сцены не рассчитывают награду и не меняют баланс напрямую; они только вызывают движок и обновляют отображение.

## 8. Роадмап после MVP

**0.2 — Отзывчивость.** Анимация ходьбы и добычи, вспышки кристаллов, звуки, экран конца захода и подсказки по первым действиям.

**0.3 — Вариативность.** 3 типа комнат: рудная жила, пещера с наградой, разрушенный лагерь. Один новый выбор между безопасностью и выгодой.

**0.4 — Долгосрочная цель.** 3 уровня глубины, достижения, небольшая коллекция редкостей. При этом оставить длину сессии короткой.

**Не делать сейчас:** мультиплеер, авторизация, backend, физика персонажа, инвентарь с десятками предметов, процедурные биомы, большая сюжетная кампания.

## 9. Риски и тесты

- **Слишком легко:** всю добычу можно собрать без выбора — уменьшить энергию или увеличить расстояние до богатых находок.
- **Слишком сурово:** игрок несколько раз подряд не может вынести даже руду — гарантировать видимые первые находки (уже есть), подстроить цены магазина.
- **Тупики:** карты с неудобной стеной — все внутренние стены разрушаемы; тесты проверяют границы и старт.
- **Потеря прогресса:** сохранение только локальное. Не обещать синхронизацию между устройствами; позже добавить экспорт/import JSON.
- **Различия API Phaser 3/4:** обновлять код по справочнику Phaser 4, не копировать устаревшие примеры с Phaser 3 без проверки.
- **Путь GitHub Pages:** base должен совпадать с именем репозитория.
